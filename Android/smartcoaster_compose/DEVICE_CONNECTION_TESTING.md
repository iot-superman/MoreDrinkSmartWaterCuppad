# 杯墊設備連線驗收

## 韌體版本

本流程使用 `WIFISET:<12 位十六進位嘗試碼>:<SSID>:<密碼>\n`，設備須回覆 `S:<嘗試碼>` 或 `E:<嘗試碼>:<錯誤碼>`。請將 `Arduino/BLE_E_Weightm7_fixappbug/BLE_E_Weightm7_fixappbug.ino` 的本次版本燒錄至 ESP32S3_SCALE；舊韌體只認得 `SSID:password`，不會回覆帶嘗試碼的結果，App 會逾時且不會進入成功頁。新韌體仍保留舊格式及既有秤重、Tare、飲水模式、RGB 與 MQTT 指令。

SSID 以 UTF-8 計最多 32 位元組，不能含冒號或換行；這是為了相容現有冒號分隔格式。一般密碼為 8–63 個 UTF-8 位元組，開放網路須在 App 明確勾選。封包使用 ATT MTU 扣除 3 位元組標頭後逐筆寫入，韌體收到換行才解析；單一設定封包不得超過 128 位元組。韌體會遮罩設定命令，不記錄密碼。

## Android 與 ESP32 實機清單

- [ ] Android 12 以上拒絕藍牙權限後，可重新要求權限；Android 11 以下拒絕定位權限後可重新要求。
- [ ] 關閉藍牙時顯示提示，重新開啟後可重新搜尋。
- [ ] 搜尋並選取 `ESP32S3_SCALE`，確認完成 GATT 服務探索及 TX 通知訂閱後才進入網路設定；選取不相容裝置時留在搜尋頁並顯示錯誤。
- [ ] 編輯 SSID、顯示/隱藏密碼及選取開放網路；驗證冒號 SSID、過長 UTF-8 SSID、無效密碼會被阻擋。
- [ ] 用有效帳密設定，只有收到本次嘗試碼的設備 Wi-Fi 成功回覆後才顯示成功頁；確認顯示實際設備名稱與 SSID，不宣稱 MQTT 已連線。
- [ ] 用錯誤密碼及不存在的 AP 測試，確認錯誤可讀、按鈕可重試，且不會顯示成功。
- [ ] 設定傳送期間關閉設備或中斷 BLE，確認錯誤狀態及重新連線/提交可用。
- [ ] 點選返回、使用 Android 系統返回及切換底部分頁，確認掃描停止、待處理設定取消、成功連線不被無故斷開。
- [ ] 檢查韌體序列埠輸出，不得出現 Wi-Fi 密碼。

Android 單元測試及建置不會取代 ESP32/手機/路由器實機驗收；目前若沒有連接實體硬體，請勿將上列實機項目標記為通過。
